# คู่มือใช้งาน Greenview Tour

ปรับปรุง 15 กันยายน 2026 · ระบบ Local / Preview

คู่มือนี้อธิบายระบบที่มีอยู่ในปัจจุบัน ชื่อปุ่มเป็นภาษาอังกฤษตามหน้าจอ เมนูและปุ่มที่เห็นขึ้นกับสิทธิ์ของบัญชี ข้อมูลที่ขึ้นต้น DEMO เป็นข้อมูลทดลอง

## 1. เริ่มงาน

เปิด Backoffice ที่ http://localhost:5174 และเข้าสู่ระบบด้วยบัญชีของตนเอง หากเข้าไม่ได้ ให้ตรวจว่าเซิร์ฟเวอร์ Local ยังทำงานอยู่ ก่อนเริ่มวันตรวจวันที่บริการในหน้า Driver, Boat และ Stock ให้ตรงกัน

เมนูสามจุดของแต่ละแถวใช้ดูรายละเอียดและทำรายการ ปุ่ม Save บันทึก ส่วน Keep editing เก็บหน้าร่างไว้ และ Discard changes ทิ้งเฉพาะสิ่งที่ยังไม่บันทึก หากระบบแจ้งว่าข้อมูลถูกแก้โดยคนอื่น ให้เปิดรายการล่าสุดแล้วตรวจใหม่

## 2. รับ Booking

1. เข้า Booking สร้างรายการ ระบุลูกค้า Agent/ช่องทางขาย โปรแกรม ผู้ใหญ่และเด็ก
2. ตรวจวันที่เดินทางและรูปแบบขากลับ โดยเฉพาะรายการที่ยังไม่กำหนดวันกลับ หรือใช้เฉพาะขากลับ
3. ตรวจบริการที่เลือก อุปกรณ์ ความต้องการพิเศษ อาหาร/การแพ้ และข้อมูลรับส่งที่เกี่ยวข้อง
4. ตรวจราคาและเงื่อนไขชำระเงิน ราคาไม่ระบุไม่เท่ากับราคา 0 บาท
5. บันทึกร่าง ตรวจรายละเอียด แล้วใช้คำสั่งยืนยันเมื่อข้อมูลพร้อม รายการยืนยันยังรอการจัดรถหรือเรือได้

หน้ารับ Booking ไม่ต้องเลือกคลังที่จะเบิกของให้ลูกค้าตามปกติ ทีมคลังเลือกแหล่งของจริงตอนเบิก ราคามาตรฐานอิงโปรแกรม Agent และวันที่ ส่วนราคาต่อรองพิเศษใช้ขั้นตอนอนุมัติในหัวข้อ 10

## 3. จัดรถและเรือ

- Driver ใช้จัดรถ คนขับ เวลาและจุดรับส่ง
- Boat ใช้จัดเรือ ทีมงาน และกลุ่มลูกค้า
- เลือกวันที่บริการ แล้วจัดลูกค้าจาก Booking ที่ยืนยันแล้วลงเที่ยวที่ถูกต้อง
- จัดขาไปและขากลับแยกกัน ตรวจจำนวนผู้ใหญ่/เด็กและความจุก่อนบันทึก
- ตรวจเอกสาร Job Order ก่อนพิมพ์ โดยดูวัน ทิศทาง เที่ยวและ revision
- หลังให้บริการ บันทึกจำนวนผู้โดยสารจริงของแต่ละกลุ่มในแต่ละขา หากน้อยกว่าที่จัดไว้ให้ระบุเหตุผล

การจัดขึ้นเที่ยวกับจำนวนเดินทางจริงเป็นคนละขั้น จำนวนขากลับไม่ได้คัดลอกจากขาไปอัตโนมัติ เอกสารที่แต่ละหน้าที่เห็นจะแสดงข้อมูลตามสิทธิ์

## 4. เตรียมของและคืนอุปกรณ์

1. เข้า Stock เลือกวันที่และเที่ยวเรือ
2. Supplies ใช้ดูของใช้ ส่วน Loans & returns ใช้ดูอุปกรณ์ยืมตามกลุ่มลูกค้า
3. ตอนเตรียมของ เลือก lot ที่มีของพร้อมใช้ ปลายทาง ผู้รับผิดชอบ และจำนวน แล้วบันทึก
4. ตอนคืน เลือกรายการเบิกและจำนวนที่จะคืน ระบุผลตามตารางด้านล่าง
5. ตรวจ Outstanding ให้เป็น 0 เมื่อจัดการของทั้งหมดแล้ว คืนบางส่วนได้ แต่คืนเกินยอดค้างไม่ได้

| ผล | ใช้เมื่อ | ผลต่อคลัง |
| --- | --- | --- |
| Return ready | คืนของสภาพปกติพร้อมใช้งาน | เพิ่มของพร้อมใช้ที่จุดรับคืน |
| Return damaged | ของชำรุด | เพิ่มของชำรุด ไม่เปิดให้เบิกเป็นของพร้อมใช้ |
| Consumed | ของสิ้นเปลืองที่ใช้ไป | ตัดยอดค้าง ไม่เพิ่มของกลับคลัง |
| Lost / wasted | สูญหายหรือทิ้ง | ตัดยอดค้าง ไม่เพิ่มของกลับคลัง |

**ไม่ต้องสร้างรายงานล้างอุปกรณ์แยกอีก** พนักงานจัดการความสะอาดตามงานประจำ และบันทึกคืนพร้อมใช้เมื่อของพร้อมจริง หากมีทั้งของปกติและของเสียหาย ให้แยกบันทึกตามจำนวน

ข้อมูลเก่าที่เป็น CLEANING ยังคงอยู่ในประวัติ หัวหน้าคลังตรวจของจริงแล้วใช้คำสั่งเปลี่ยนสภาพที่ Inventory เป็น Ready หรือ Damaged พร้อมจำนวนและหมายเหตุ ไม่ต้องเปิดงานล้างซ้ำ ยอดนี้จะอยู่ใน Legacy cleaning balances จนจัดการครบ

## 5. ปิด Booking และสรุปวัน

ก่อนใช้ Complete ตรวจว่าจัดรถ/เรือครบทุกขาที่ร้องขอ บันทึกจำนวนผู้โดยสารจริงแล้ว เบิกของครบ และจัดการคืน/ใช้/สูญหายจนไม่เหลือยอดค้าง รายการที่ยังไม่กำหนดขากลับต้องจัดการให้ชัดเจนก่อน

หากปิดไม่ได้ อ่านข้อความที่ระบบแสดงแล้วกลับไปแก้ขั้นตอนนั้น Complete เป็นการปิดงานบริการ ไม่ใช่การรับรองว่ารับชำระเงินแล้ว

Daily summaries ใช้ตรวจและเก็บสรุปตามวันที่ การเก็บสรุปไม่ล็อกการแก้ Booking หากมีแก้ไขให้สร้าง revision ใหม่ ระบบ Local ยังไม่ส่ง LINE อัตโนมัติ

## 6. คลังและงานบริษัท

| เมนู | วิธีทำงาน |
| --- | --- |
| Inventory | ดูยอดตามของ lot สถานที่และสภาพ รับของ โอน หรือเปลี่ยนสภาพตามสิทธิ์ |
| Stock movements | ค้นประวัติด้วยชื่อของ สถานที่ หรือหมายเหตุ รวมถึงรหัส Booking ที่ระบุไว้ |
| Stock requests | สร้างคำขอ → ส่งอนุมัติ → ผู้ตรวจอนุมัติ → เบิกจริง → คืน/บันทึกใช้ |
| Stock counts | บันทึกยอดนับจริงและเหตุผล → ส่งตรวจ → ผู้ตรวจอนุมัติปรับยอด |
| Warehouse custodians | ระบุผู้รับผิดชอบคลัง |
| Maintenance jobs | แจ้งซ่อม → ตรวจอนุมัติ → ผู้รับงานรายงานเสร็จ → ผู้ตรวจรับงาน |
| Purchasing | ขอซื้อ → อนุมัติ → รับของทั้งหมดหรือบางส่วนตามจำนวนจริง |

รับซื้อเฉพาะจำนวนที่มาถึงจริง ส่วนที่ยังไม่รับไม่เพิ่มคลัง การรับของไม่สร้างประวัติจ่ายเงินเอง

งาน Housekeeping เป็นงานพื้นที่ เช่น พื้นและชั้นวาง แยกจากการล้างอุปกรณ์ที่นำออกแล้ว หากใช้งาน ให้สร้าง Cleaning zones → ตารางงาน → Generate scheduled jobs → ผู้รับผิดชอบ Report completed → ผู้ตรวจอีกคน Accept work หรือ Return to worker

## 7. บุคลากรและการเงิน

Employment เก็บข้อมูลการจ้าง ส่วน Attendance & rest เก็บวันทำงาน พัก ลา และผู้ทำแทน การไม่มีชื่อใน Job Order ไม่ถือว่าขาดงานหรือหักเงินเอง

รายการการเงินใช้ลำดับ Save draft → Submit → ผู้ตรวจอีกคน Approve/Reject หากถูกตีกลับให้ Revise แก้ไขและส่งใหม่ ผู้รับเงินไม่อนุมัติหรือบันทึกการจ่ายให้ตนเอง

- Payroll: ระบุงวด ยอดฐานและหลักเกณฑ์ฐาน รายการเพิ่ม/หักต้องมีเหตุผล ระบบรวมยอดให้ตามที่กรอก
- Trip allowances: ระบุเบี้ยเลี้ยงที่สัมพันธ์กับ Job Order
- Reimbursements: ระบุค่าใช้จ่ายและ reference/ลิงก์หลักฐาน
- Work advances: ขอเงินทดรอง เมื่อจ่ายและใช้งานแล้วสะสางค่าใช้จ่ายพร้อมหลักฐานและเงินคืนให้เท่ายอดทดรอง แล้วส่งตรวจ
- Salary advances: บันทึกเงินเดือนล่วงหน้าแยกจากเงินเดือน ไม่มีการหักอัตโนมัติ
- Supplier payments: ผูกคำขอจ่ายกับการซื้อและของที่รับจริง

**Record payment ใช้บันทึกการจ่ายภายนอกที่เกิดขึ้นแล้ว** พร้อมวันที่และเลขอ้างอิง ปุ่มนี้ไม่โอนเงิน อย่าบันทึกการจ่ายสมมุติเพื่อทดสอบบนข้อมูลจริง

## 8. สิทธิ์และการแก้ปัญหา

หากไม่เห็นเมนู ให้ผู้จัดการตรวจสิทธิ์ของบัญชีที่ Users ไม่ใช้บัญชีผู้อื่นแทน หากเซฟไม่ผ่านให้เก็บร่างและอ่านข้อความผิดพลาด หลีกเลี่ยงกดซ้ำขณะกำลังบันทึก หากรายการถูกแก้พร้อมกันให้เปิดฉบับล่าสุดเพื่อตรวจความต่างก่อนส่งใหม่

หากเบิกไม่ได้ ให้ตรวจของพร้อมใช้ จำนวน lot วันหมดอายุ และรายการ Booking หากคืนไม่ได้ ให้ตรวจยอดค้างและจุดรับคืน หากอนุมัติไม่ได้ ให้ตรวจสถานะ สิทธิ์ และผู้สร้าง/ผู้รับประโยชน์ที่ต้องแยกจากผู้ตรวจ

## 9. ขอบเขตที่ต้องพัฒนาต่อ

การอัปโหลดหลักฐาน/เอกสารสัญญา, บัญชีเต็มรูปแบบ, นโยบายคำนวณภาษีและเงินเดือนอัตโนมัติ และระบบออนไลน์/LINE ต้องทยอยตกลงรายละเอียดก่อนเปิดใช้ คู่มือจะปรับตามฟีเจอร์ที่ส่งมอบจริง

## 10. ราคาต่อรอง Agent ราย Booking

1. บันทึก Booking แบบ Draft พร้อม Agent โปรแกรม จำนวนคนและบริการให้ครบก่อน
2. เปิดเมนูสามจุด → **Agent negotiated price** ระบบโหลดข้อมูล Booking ล่าสุด
3. ตรวจราคามาตรฐานและยอดรวม ใส่ **Proposed adult price / Proposed child price** เป็นราคาต่อคน (ใส่ 0 ได้) พร้อม **Negotiation reason** แล้วกด **Request price approval**
4. สถานะราคาเป็น **PENDING** ราคาที่บันทึกใช้งานยังเป็นมาตรฐาน และยัง Confirm Booking ไม่ได้
5. ให้ Manager คนละคนกับผู้ขอเปิดเมนูเดียวกัน ตรวจโปรแกรม วันเดินทาง จำนวนคน บริการ ราคาเสนอ ส่วนเพิ่ม/เครดิตคืน และเหตุผล ใส่เหตุผลตรวจแล้วเลือก **Approve price** หรือ **Reject price**
6. เมื่อ **APPROVED** ระบบใช้ราคาต่อรองคำนวณยอดรวม จึง Confirm Booking ได้เมื่อข้อมูลด้านอื่นพร้อม
7. ถ้า **REJECTED** ให้แก้ราคาและส่งคำขอใหม่ หรือเลือก **Use standard price** พร้อมเหตุผลเพื่อกลับไปใช้ราคามาตรฐาน

การแก้ Draft แล้วบันทึกจะคืนราคามาตรฐานและล้างคำขอราคาพิเศษ ต้องส่งคำขอใหม่หลังแก้เสร็จ การส่งราคาใหม่แทนที่คำขอที่อนุมัติแล้วก็ต้องอนุมัติใหม่เช่นกัน ประวัติคำขอ/ผลตรวจเก็บในบันทึกการเปลี่ยนแปลง ราคาพิเศษใช้กับ Booking นี้เท่านั้น ไม่แก้ราคากลางของ Agent และไม่รวมการรับหรือจ่ายเงินจริง

Booking ที่ยืนยันแล้วไม่เปิดแก้ราคาด้วยขั้นตอนนี้ ผู้ไม่มีสิทธิ์หรือผู้ขอเองจะไม่เห็นปุ่มอนุมัติ การขาด Manager อีกบัญชีต้องจัดผู้ตรวจจริงก่อนใช้งานครบขั้นตอน

## 11. ลูกหนี้ Agent และเอกสารที่บริษัทออกเอง

### สรุปยอดเรียกเก็บภายใน

1. เปิด **Accounts & Finance → Agent receivables** แล้วเลือก **Create internal statement**
2. ตั้งชื่อสรุปและวันครบกำหนด เลือก Booking ที่จบทริปแล้ว (`COMPLETED`) และมีเงื่อนไข `AGENT_CREDIT` ของ Agent เดียวกัน สูงสุด 50 รายการต่อสรุป
3. ตรวจยอดและรายการก่อนบันทึก ระบบเก็บราคาขณะออกสรุปและกัน Booking ซ้ำกับสรุปอื่น
4. เปิดสรุปเพื่อดูยอดรวม รับแล้ว และคงค้าง หากยังไม่ได้รับเงินเลย สามารถ **Void unpaid statement** พร้อมเหตุผลเพื่อจัดรายการใหม่ได้ ประวัติสรุปเดิมยังอยู่

สรุปนี้เป็นเอกสารภายใน บริษัทออกใบเสร็จและใบกำกับภาษีเองตามวิธีที่ใช้อยู่ ระบบไม่มีการออกเอกสารภาษีแทนบริษัท

### รับชำระและแนบภาพ

1. เมื่อรับเงินจริงจากภายนอกแล้ว เปิดสรุป → **Record received payment**
2. ใส่จำนวนเงิน วันที่รับ และเลขอ้างอิง ตรวจให้ครบก่อนบันทึก รับบางส่วนได้ แต่ไม่เกินยอดคงค้าง
3. ในแถวรับชำระ กด **Documents for … → Attach document** เพื่อแนบใบเสร็จ/ใบกำกับภาษี/หลักฐานรับเงินของรายการนั้นโดยตรง
4. เลือกไฟล์ภาพ JPEG/PNG หรือ PDF ขนาดไม่เกิน 5 MB ใส่ประเภท เลขที่เอกสารบริษัท และหมายเหตุ แล้วกด **Attach document**
5. ใช้ **Download** เพื่อเรียกไฟล์เดิม ผู้ใช้ต้องยังมีสิทธิ์เข้าถึงรายการจึงดาวน์โหลดได้

แนบเอกสารได้ที่ Booking → **Supporting documents** และหน้ารายการบุคลากร/การเงิน → **View** ด้วย การแนบภาพไม่เปลี่ยนยอดรับชำระ ไฟล์และรายการรับชำระที่บันทึกแล้วเก็บเป็นประวัติ ไม่สามารถเขียนทับหรือลบผ่านหน้าจอรอบนี้ หากบันทึกรับเงินจริงผิดต้องให้ผู้ดูแลตรวจสอบก่อนใช้ยอดนั้นต่อ; ยังไม่มีรายการกลับบัญชีในรอบนี้

### เงินเดือน CSV

ผู้มีสิทธิ์ `payroll.view` เปิด **Payroll** ตั้งตัวกรองชื่อ/สถานะ แล้วกด **Export filtered payroll CSV** ระบบส่งออกทุกรายการที่ตรงตัวกรอง สูงสุด 5,000 รายการ พร้อมฐานเงินเดือน เงินเพิ่ม หัก ยอดสุทธิ เหตุผล และข้อมูลการจ่ายที่บันทึกไว้

สูตรในรอบนี้ใช้ฐานเงินเดือนที่บริษัทกำหนด + รายการเพิ่ม − รายการหักพร้อมเหตุผล ไม่คำนวณภาษี ประกันสังคม หรือส่งคำสั่งโอนธนาคารอัตโนมัติ ไฟล์ CSV มีข้อมูลเงินเดือนส่วนตัว ให้เก็บตามแนวทางบริษัท
