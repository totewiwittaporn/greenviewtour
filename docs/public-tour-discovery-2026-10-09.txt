SITEMAP
Existing /sitemap.xml keeps27 canonical static public URLs and appends deduplicated
/tours?tour=<encoded-slug> URLs from every existing publicCatalog cards page, without
an ownership filter. That backend contract already enforces ACTIVE+PUBLISHED and
includes GREENVIEW and PARTNER. No backend API/schema/auth changes needed.
Use lean existing cards data (12 rows/page), never editable/detail graphs. Validate
page/total/size, expected row count, ownership/id/slug and repeated IDs. Changed totals,
missing pages, invalid JSON, upstream errors, timeout or bounds return503 no-store
with Retry-After60; never return a successful partial/static-only fallback on failure.
A valid empty catalog returns200 with exactly27 static URLs and no invented tours.
Slugs are URI-encoded, full loc values XML-escaped; no private hosts or date/pax/filter
variants enter the sitemap. Sorting/deduplication is deterministic.

Resource bound: maximum100 catalog pages/1200 rows per build and a shared10second
fetch deadline. Exceeding the bound is503, not silent truncation. Future growth beyond
this limit needs a paginated sitemap/index design before crossing the threshold.
Complete successful results only are cached for60seconds in Cloudflare Cache API
under a versioned internal key, with public max-age60. HEAD has the same status/MIME
without body. Cache failure falls back to fresh generation. Publishing/unpublishing
can take up to cache TTL to appear; all data is read-only and public-filtered.
The existing paginated API does not offer a cross-page transactional snapshot:
detected count/duplicate/shape drift fails closed; equal-count concurrent edits may
be reflected on the next rebuild. No stronger snapshot consistency is claimed.

PAGINATION / INDEXING
Public own/Partner catalog and promotions parse page from URL; active numbered and
previous/next controls are real anchors, preserving filters/date/pax/other query
values. First-page links omit page. Existing known-route navigation handles SPA
transitions and browser back/forward; direct visits/reloads use the same page.
Private-app pagination and shared backend read models unchanged.
Plain /tours?page=N and /promotions?page=N are self-canonical; page1 canonical omits
page. Filter/travel/unknown query combinations receive noindex,follow at Worker and
rendered metadata. Filtered canonical preserves ownership/duration/page, drops travel
inputs. Out-of-range page responses use backend-clamped canonical plus noindex in
rendered UI. No new redirects. Both detail entry routes canonicalize to
/tours?tour=<slug>; query variants and /promotions detail aliases are noindex,follow.
Plain valid tour details remain indexable. Missing/unavailable detail protections
from PR32 remain. React metadata cleans up between routes.
These are rendered SPA anchors/metadata, not server-rendered HTML expansion.
