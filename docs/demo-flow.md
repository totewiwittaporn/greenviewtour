# DEMO FLOW — ทดลองตามการไหลของข้อมูล

ข้อมูลสาธิตชุด `DEMO-FLOW-260913` ใช้วันเดินทาง **20 กันยายน 2026** (โปรแกรมค้างคืนกลับวันที่ 21) ชื่อรายการขึ้นต้น `DEMO FLOW` ราคา สัญญา ยอดสต๊อก และสถานะการเดินทางทั้งหมดเป็นข้อมูลสมมุติ ไม่ใช่รายการจริง สัญญาตัวอย่างไม่มีลายเซ็นหรือเอกสารรับรอง

## เปิดดูตามลำดับ

1. **Settings → Partners & Sales**: Agent 2 ราย ผู้จัดทัวร์ ผู้ให้บริการรถ และผู้จำหน่ายสินค้า → ข้อตกลงตัวอย่าง 2 ฉบับ → ราคา Agent 12 รายการ → ช่องทางขาย 3 ช่องทาง
2. **Settings → Tour programs & services**: โปรแกรม 6 แบบ ได้แก่ วันเดียว ค้างคืน เปิดวันกลับ ขาไป ขากลับ และทัวร์พันธมิตร ดู Components เพื่อเห็นบริการรวม/บังคับ/เสริม และจำนวนที่คำนวณตามผู้ใหญ่ เด็ก หรือคืนพัก
3. **Settings → Transport & Pickup**: โรงแรม 4 แห่ง จุดรับ/ท่าเรือ/สนามบิน รถและเรือ 5 คัน/ลำ
4. **Settings → Equipment & Supplies**: อุปกรณ์ 7 รายการ วัสดุสิ้นเปลือง 6 รายการ และคลัง 4 จุด บริการอีก 10 รายการอยู่ใน Tour programs & services
5. **Booking** (`/operations/bookings`): ค้น `DEMO FLOW` แล้วเปิดตัวอย่าง 00–09 ตารางด้านล่างอธิบายแต่ละกรณี หมายเลข Booking จริงสร้างด้วยระบบปกติ จึงให้ค้นจากชื่อ
6. **Operations → Driver / Boat**: เลือกวันที่ `2026-09-20` มีงานเรือและรถอย่างละขาไป/กลับ ดู Booking ที่ถูกจัดลงงาน จากหน้า Boat เปิดเตรียมของและเอกสาร Job Order
7. **Stock / Loans & returns**: เปรียบเทียบตัวอย่าง 03 ที่เบิกแล้วค้างคืน กับ 09 ที่คืนแล้ว อุปกรณ์ที่คืนแยกเป็นรอล้าง หน้ากากล้างเสร็จ 1 ชิ้นแล้ว
8. **Inventory → Stock balances / Stock movements**: ตามรายการรับเข้า โอนน้ำ 2 แพ็กเป็น 24 ขวดไปคลังเกาะ เบิก ใช้หมด คืน และเปลี่ยนสภาพ อะไหล่ชำรุด 2 ชิ้นถูกแยกจากยอดพร้อมใช้
9. **Daily summaries**: เลือกวันที่เดียวกันเพื่อดูภาพรวมงานที่จัดแล้ว Snapshot นี้ไม่ปิดการรับ Booking และไม่ส่ง LINE

## ขอบเขต

- ชุดทัวร์เดิมใช้บริษัทและเจ้าหน้าที่เรือ DEMO เดิม ไม่สร้างบัญชีล็อกอินหรือส่งข้อความ ส่วนชุดงานบริษัทที่เพิ่มภายหลังแต่งตั้งหน้าที่ทำความสะอาด/ดูแลคลังเฉพาะผู้ใช้ DEMO ตามรายละเอียดในคู่มือด้านล่าง ไม่เปลี่ยนหน้าที่พนักงานจริง
- งานรถจงใจรอคนขับ เพราะยังไม่มีผู้ใช้ DRIVER ที่ใช้งานได้ ไม่ใช้บุคคลจริงแทนตัวอย่าง
- เพิ่มงานบริษัทแล้ว: แม่บ้าน/ตารางตามโซน, ผู้ดูแลคลัง/เบิกคืน/ตรวจนับและซ่อมบำรุง, จัดซื้อและรับบางส่วน, บุคลากรและการเงิน รวมถึงเงินเดือน/เบี้ยเลี้ยง/เบิกเงิน/เงินทดรอง ดู [คู่มือทดลองงานบริษัท](company-workflow-guide.md) เพื่อเดินต่อจากคลังและ Job Order เดิม
- โปรแกรม/ราคาในชุดนี้เป็นข้อมูล Backoffice ไม่มีการเผยแพร่เว็บไซต์หรือสร้างรายการรับเงินจริง
- รายการเดิมทั้งหมดคงอยู่ ไม่ควรนำยอด DEMO ไปรวมรายงานทางธุรกิจจริง

## สำหรับผู้ดูแล

จาก root ของ repository ใช้ Node รุ่นตาม package.json และ dependencies ที่ติดตั้งแล้ว:

```sh
node backend/scripts/seed-demo-flow.js
```

ค่าเริ่มต้นตรวจทั้งชุดใน transaction และ rollback; เพิ่ม `--apply` เพื่อบันทึกทั้งชุดแบบ atomic ใช้ `--env-file <path>` เมื่อไฟล์เชื่อมต่ออยู่ใน checkout อื่น โปรแกรมตรวจ project ref และ environment ก่อนเขียน ไม่เก็บ credentials ลง Git

สคริปต์เรียกบริการเดียวกับ API สำหรับ catalog, Booking, dispatch และ stock; ไม่แก้ตาราง Auth โดยตรง ไม่มีการส่งอีเมล/LINE และไม่เปิด server การรันซ้ำหลังบันทึกแล้วจะรายงาน `ALREADY_PRESENT` โดยไม่เติมสต๊อกซ้ำหรือเปลี่ยนสถานะที่ผู้ใช้ทดลองแก้ หากพบชุดข้อมูลไม่ครบ/ชน ID ให้ตรวจสอบก่อน ไม่ใช้สคริปต์นี้ซ่อมหรือล้างข้อมูล

## ชุดงานบริษัทที่เพิ่มต่อจากข้อมูลทัวร์

ชุด `DEMO-COMPANY-260913` เชื่อมคลัง เครื่องมือ น้ำดื่ม เรือ ผู้จำหน่ายและเจ้าหน้าที่ DEMO ที่มีอยู่แล้ว จุดเริ่มต้นที่บันทึกไว้มีงานทำความสะอาด/ตรวจนับ **14 งาน** และรายการบุคลากร/การเงิน **9 รายการในสถานะ Draft** ไม่ใช่รายการจ่ายเงินจริงทั้ง 9 รายการ

ลองเปิด Purchasing ดูคำสั่งซื้อ 24 ขวด รับแล้ว 12 ขวด (120 บาท) และตามต่อ Supplier payments ที่ยังเป็นร่าง ส่วน Stock requests มีตัวอย่างเบิกเครื่องมือ 3 ชุด คืนแล้ว 2 ชุด เหลือค้าง 1 ชุด การตรวจนับต่างหากลดจำนวนตามที่ตรวจพบหลังอนุมัติ จึงไม่ควรนับเป็นการคืนเครื่องมือ

เงินเดือนตัวอย่างใช้ยอดฐาน 10,000 บาท หักตัวอย่างพร้อมเหตุผล 100 บาท เหลือ 9,900 บาท โดยยังเป็นร่าง ต้องตรวจและอนุมัติรายงวด ไม่มีสูตรหาร 30 หรือหักวันหยุดอัตโนมัติ รายละเอียดเส้นทางเมนูและสิทธิ์ผู้ตรวจอยู่ใน [คู่มืองานบริษัท](company-workflow-guide.md)

สคริปต์เพิ่มเติมคือ `node backend/scripts/seed-company-workflows.js` ซึ่งค่าเริ่มต้นตรวจแบบ rollback; `--apply` ใช้บันทึกจริง และ `--env-file <path>` เลือกไฟล์เชื่อมต่อ การรันซ้ำพบ marker แล้วคงข้อมูลและการแก้ไขปัจจุบันไว้ ไม่เติมสต๊อกหรือเปลี่ยนสถานะซ้ำ
